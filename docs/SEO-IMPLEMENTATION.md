Implementation date: 2026-09-15. This is an implementation and measurement record, not a claim about achieved rankings.

## Canonical host and language architecture

Canonical origin: **https://www.caribbeanvoodoo.mx**. Vercel's existing redirect already chooses this host. Its saved CLI login was invalid during this session, so all code signals were aligned to the working host. This resolves the conflicting signals without an account change. The homepage's canonical omits the trailing slash, consistently with Next's metadata serialization.

If the owner later wants the shorter origin, change Vercel's primary domain to the apex and redirect www to it, then change SITE_URL in src/data/site.config.ts. Deploy these together and re-check every metadata/sitemap URL. Never add a www-to-apex application redirect while Vercel redirects apex-to-www: that would create a loop. HTTP-to-HTTPS normalization is controlled by Vercel and can create an additional hop; check all four protocol/host combinations in production.

Spanish stays at / and English at /en. Both languages arrive fully rendered from the server. src/middleware.ts overwrites the internal locale header from the requested URL; src/app/layout.ts reads it and supplies the correct HTML lang and LocaleProvider value. A supplied client header cannot select the language. Neither cookies nor localStorage override the URL. Language controls are normal anchor links to equivalent pages.

Every content page has its own canonical plus reciprocal es-MX, en and x-default (Spanish) links. English pages are not canonicalized to Spanish. The Open Graph locale reflects each page. Root HTML is es-MX or en. Page-level metadata is generated by src/lib/seo.ts.

Tradeoff: page documents are server-rendered on demand rather than statically generated. This keeps date-sensitive show lists current without requiring a new deployment when a concert passes. No backend lookup is added to a page render. Fonts, JS, CSS and artwork retain normal asset caching; robots and sitemap remain generated assets. Sitemap lastModified values are explicit content dates, not rebuild timestamps.

## Content and structured data

Each page emits one JSON-LD graph. All schema builders are checked against schema-dts's Schema.org types. JSON-LD serialization escapes < to avoid accidental script termination.

- WebSite: stable /#website identity.
- MusicGroup: stable /#band, current three-person roster, Tulum origin, confirmed founding month, logo, contact and direct artist profiles. Instagram, YouTube, Spotify artist and Apple Music artist identities are used in sameAs, not a release smart link.
- WebPage: its localized URL, title, description, language and connection to the band/site.
- BreadcrumbList: the visible home link plus current page on detail pages.
- MusicAlbum: stable /#release-[slug] for the two albums and the Kamikaze single. Unreleased DarkPsycho has no invented release date or released recordings. Its announced tracklist is visible text.
- MusicRecording: released tracks nested under Serpientes and Kamikaze, linked to the band and release. No invented ISRCs, duration or credits.
- VideoObject: on the dedicated Kamikaze watch page; an actual iframe is in the initial HTML. Confirmed YouTube upload timestamp 2026-08-16T22:34:29-07:00 (August 17 UTC), duration PT2M46S, thumbnail and embed URL. It is a separate date from the single's August 14 release.
- MusicEvent: only for non-past entries with confirmed time and structured full address. Cancelled/postponed status is supported when confirmed in data. No inferred ticket availability. Offer requires both a real ticket URL and a known price; no offers for cancelled/postponed events.

MusicGroup/MusicAlbum/MusicRecording are useful Schema.org entities but do not guarantee a Google rich result or Knowledge Panel. Rich Results Test supports specific Google features; Schema.org validity and Google eligibility are different checks. Production Google Rich Results/URL Inspection checks require the deployed URLs and are listed below.

## Event lifecycle

All three existing August 2026 shows remain at their original Spanish URLs and have English counterparts. They are listed in the concert archive, not as upcoming. Archived pages show a past-date label, omit MusicEvent/Offer markup, remove reservation CTA links, and offer notifications about future dates instead. The former October 31 slug remains 404.

src/lib/events.ts compares the supplied current time with a confirmed endDateTime; without an end time it uses the end of the venue-local calendar day. This avoids hiding a show at door-opening time or inventing a duration. The helper accepts an explicit clock so timezone boundaries can be tested.

Add future concerts in src/data/shows.ts. Set fullAddress, startDateTime including offset, endDateTime when known, ticketUrl only when real, status when confirmed, optional flyer, localized description, and modified. Karunna and Rockstar Burger still need full street addresses. Mora Mora's address is confirmed in the supplied event information. Date-only or unconfirmed-time shows remain useful visible pages without qualifying event markup.
